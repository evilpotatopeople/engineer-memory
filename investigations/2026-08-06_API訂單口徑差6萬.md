# HeroMama API 訂單數 vs 報表口徑差 6 萬 — /investigate
日期：2026-08-06
Skill：/investigate
狀態：已結案

## 摘要（一句話）
同事用 Metorik API 抓 HeroMama TW 得 206,235 筆、交接文件寫 146,537，兩個數字**都對**——API 是資料庫全部訂單物件、146,537 是拍板 segment 報表口徑（成交 status＋市場國家＋排 bacs/cheque＋排 ToB＋有 cid），差額 6 萬全部可歸因、無資料遺失。

## 詳細內容

### 背景
同事的 Claude 建 fetcher 前跑 probe：TW API 206,235 vs 交接 146,537（71.1%）、HK 46,834 vs 42,791（91.4%）。他驗了「status 全列加總＝總數」與「兩 store 比值不同」後下結論：**「沒有規則可以找、API 是唯一權威來源、文件訂單數不可靠」**。使用者核對 Metorik 後台確實 ~14 萬、來問為什麼 API 會多出 6 萬。

### 拆解方法
用本機 pipeline 的 Metorik API key（`_experiments/metorik_spike/credentials.yml`）、`/orders` + filters + per_page=1、對 page 做 binary search 取精確筆數（不拉資料、只讀 pagination meta）。ToB 訂單用 `/customers` role≠customer 名單 + `customer_id in [...]` chunk 查。

### TW 瀑布（2026-08-06 快照）
| 步驟 | 筆數 | 該層排除 |
|---|---|---|
| API 全部訂單 | 206,576 | — |
| 排 cancelled 14,072／refunded 418／pending 240 | 191,845 | −14,731 |
| 只留出貨國 TW（混站期港澳/國外單） | 181,655 | −10,190 |
| 排 payment bacs/cheque（多為批發/寄倉） | 168,784 | −12,871 |
| 排 guest（無 customer_id） | 168,778 | −6 |
| 排 ToB 客（role≠customer 881 個、339 個有單、全站共 33,309 筆） | **148,311** | −20,467 |

148,311 vs 交接 146,537 = **+1,774 ≈ 交接快照後的自然成長**。master CSV 當日實數 **146,881**（差 1,430、<1%，來自 daily sync 時滯與 country fallback 等 client 端細節）。

### HK 瀑布（同日）
46,953 全部 → 排 status 1,936 → 港澳外 0 → 排 bacs/cheque 31 → 排 ToB 2,042 → **42,944** vs 交接 42,791（+153 成長）。master 實數 42,920（差 24、0.06%）。

### 同事推理的兩個洞
1. **「status 加總＝總數 → 不是狀態篩掉的」是套套邏輯**：API 自己的 status 分解永遠加總等於自己的總數。他只驗了 status 一個維度就下「沒有隱藏規則」的總結論——實際規則是四個維度（status＋country＋payment＋role），而且全寫在自家 repo `_shared/METORIK_SYNC_SPEC.md` 的拍板 segment 段落。
2. **「兩 store 比值不同（71% vs 91%）→ 沒有系統性規則」推論不成立**：同一條規則套在不同市場結構、比值本來就不同。TW 有大量寄倉/批發 ToB（單一寄倉帳號 cid 13753 就 14,746 筆＝全庫 7%）＋混站期非 TW 單 10,190 筆；HK 這兩塊近乎為零。規則相同、資料分布不同。

### API 技術備忘（Metorik `/orders` filters）
- pagination meta 無 total、要 binary search page 取 count
- `role` filter 在 orders 端無效（eq/neq 都回 0、要走 /customers 拉名單）
- `customer_id in [...]` 的 list 長度上限在 20-30 之間、**超過靜默回空**（不報錯）——用 20 一組
- `shipping_address_country`／`payment_method`／`total`／`status` filter 都有效（TW＋非TW＝總數驗證通過）
