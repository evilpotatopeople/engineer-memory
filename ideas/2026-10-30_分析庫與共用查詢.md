# DTC 分析庫與共用查詢入口 — /office-hours
日期：2026-10-30
Skill：/office-hours
狀態：進行中（設計待核可）

## 摘要（一句話）
同事的 AI 要查資料，不能直接接 `dtc.duckdb`：每天另建不含個資的分析庫，放進公開資料夾，由獨立帳號 `dtc-api` 的查詢服務提供五個工具與受限 SQL，登入走 Cloudflare。

## 詳細內容

完整設計文件：`~/.gstack/projects/Claudetest/hsuyutong-main-design-20261030-183450.md`（副本：`~/Desktop/Claude test/research/analysis-db-design/設計文件_2026-10-30.md`）

### 本輪最重要的發現
- `aggregate_viewer` 的 API／MCP 雛形已存在，但查詢快照是整份複製、含 `customer_pii`，不能接自由 SQL。
- 現況是隔離＋雜湊，不是去識別；`customer_id`、訂單編號、`person_id` 都在，email 雜湊未加鹽。
- 討論途中發現 dashboard 下載名單與側欄排除客戶都會露出個資，當天已修並上 Air（1ce47ab、5178b6f）。
- 分析庫試建 9.5MB、約 2 秒。DuckDB 沙箱 17 條攻擊實測只有暫存表放行，再用「只准 SELECT」擋掉。
- Air 只有 Python 3.9、沒有加密套件，RS256 用標準函式庫驗；官方 MCP SDK 跑不了，要自寫無狀態 HTTP 層。

### 三輪審稿抓到、我原本想錯的
- `v_orders_paid` 沒濾 $0 單，業績要再加 `total > 0`。
- 「只開分析庫」原本只是程式約定，同帳號沒有系統層保障，改用獨立帳號。
- 商品幾單的正式數字要沿用 `product_orders.build_sql`，品類表加總對不上 scope，且正式標記要看完整度。
- 新步驟不能接在 Stage 3 之後，要接在 post-hook 驗證之後，同輪成功通知還會刪共用警告檔。
- 服務程式在 `~/Desktop`，`dtc-api` 讀不到，要發布副本。
- 一張單跨產品線會重複算，品類層不能由產品線加總。

### 選定方案
Approach B（分析庫＋固定工具＋受限 SQL，跑在 Air），估 7–10 工作天。先做步驟 0：驗 Cloudflare 登入＋Claude 連線，以及 `dtc-api` 帳號隔離，不過就停。

### 被否決的
- 直接接現有資料庫：個資外露、無法分品牌、AI 寫的 SQL 會繞過口徑。
- 只擴充固定查詢：對外服務仍開著含個資的檔案。
- 推到 Cloudflare Workers：要重寫，且銷售資料上雲要公司另外同意；分析庫是獨立檔案，之後還能走。
